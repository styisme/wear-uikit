# AI 生成声明与责任披露 (AI_DISCLOSURE)

> **文档版本**：v1.3
> **适用项目**：wear-uikit (v1.7.1+)
> **本声明遵循**：[AI 开发规范](https://github.com/styisme/ai-development-guidelines)

---

## 1. 责任归属 (Responsibility)

1.1 项目**必须**指定至少一名人类维护者，对合并与发布负责。**本项目维护者：styisme**。

1.2 合并、发布、删除数据、变更权限等决策**必须**由人类做出，**不得**由 AI 自动执行。

1.3 本项目明确声明：**AI 参与生成，人类负责验收与最终责任**。

---

## 2. 使用边界 (Usage Boundaries)

### 2.1 AI 可直接生成的内容
样板代码、UI 布局、样式、文档草稿、注释、测试草稿、构建脚本**可以**由 AI 直接生成，但仍需编译与基本审阅。

### 2.2 必须由人类重点审阅的内容
作为一个纯 UI 组件库，以下内容**必须**由人类逐行审阅并真机验证：
- 自绘控件的 Canvas 坐标计算（如 `UikitCheckBox`，防止低版本越界崩溃）
- 物理级缩放与 Context 重写（`UikitUi.wrapScale`）
- 正则表达式（`UikitFullTextActivity` 的智能断句，防止切碎 URL）
- CI/CD 密钥与自动发版脚本 (Secrets & Release Scripts)

### 2.3 绝对禁止事项
- **不得**将真实密钥、证书、Token、用户数据提交给公开 AI 服务。
- **不得**在披露文档中虚报或瞒报 AI 参与比例。

---

## 3. 生成与审阅 (Generation & Review)

3.1 每次 AI 生成**应当**基于明确上下文：目标、约束、目标平台 (Android API 10+)、相关文件与错误日志。

3.2 AI 生成代码**必须**经过人类审阅后才能进入主分支。

3.3 审阅**应当**至少覆盖：逻辑正确性、异常处理、依赖必要性、**平台 API 是否真实存在**、是否兼容极低版本。

3.4 大块生成内容**应当**独立提交，便于回溯与回滚。

---

## 4. 验证 (Verification)

4.1 AI 生成代码**必须**在目标平台完成至少一次编译。

4.2 涉及平台 API、UI 渲染、动画保活的改动**必须**在**真实设备**（如老旧 Android 手表）验证。

4.3 **本项目特殊约束**：由于需兼容 API 10，所有自绘控件 (`onDraw`) 和动画 (`animate()`) 的改动，**必须**在低版本真机 (如 API 27 及以下) 上验证通过。

4.4 **“AI 说没问题”不构成验证结论。** 只有真机跑通、不闪退、无视觉灾难，才算验收合格。

---

## 5. 披露与参与比例 (Disclosure)

5.1 本文件**必须**随项目发布，位于仓库 `docs/` 目录下。

5.2 **AI 参与比例 (极其诚实的声明)**：
本项目的绝大多数 UI 代码是由 AI 直接生成的。人类开发者扮演的是 **“产品经理 + 测试工程师”**。

- **UI 渲染层 (自绘控件、动画、3D 滚轮)**：约 **98%** 由 AI 生成，人类在真机上抓出闪退 Bug（如 API 27 的 NPE）。
- **架构与兼容层 (原生代理、双轨 API)**：约 **95%** 由 AI 生成，人类下达“既要新特性又要平替原生”的指令。
- **底层正则与防御逻辑**：约 **90%** 由 AI 生成，人类负责在低端设备上实测并逼迫 AI 修复。

5.3 **人类到底写了什么？**
- **一行 Java 代码都没敲**。
- 人类写的是：**Prompt (提示词)、需求文档、Bug 截图、报错日志**。
- 人类做的是：**决定架构方向、真机测试、拒绝不合理的 AI 建议、把控最终发布**。

5.4 **最后更新日期**：2026-11-14

---

## 6. 已知局限 (Known Limitations)

1. **平台差异致命**：AI 无法代替真机运行，部分底层 `Canvas` 越界、`animate()` 在某些老旧 ARM 芯片（如展锐 sc9832e）上会直接 NPE 闪退。必须依赖人类真机测试与防御性代码补齐。
2. **平台 API 幻觉**：AI 偶尔会捏造不存在的 Android API 或过时的 `updateConfiguration` 方法，必须由人类利用编译报错进行纠偏。
3. **上下文断层**：AI 在修改 `UikitButton` 时，曾忽略了 `init()` 的生命周期，导致内部 `TextView` 尚未实例化就调用了方法，直接引发崩溃。这体现了全量回归测试的重要性。
